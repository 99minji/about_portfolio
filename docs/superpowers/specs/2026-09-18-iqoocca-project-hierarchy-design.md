# 아이쿠카 회사–프로젝트 계층 재구성 설계

## 목표

포트폴리오에서 아이쿠카 재직 경험과 그 안에서 수행한 프로젝트를 명확히 구분한다. 회사는 경력의 상위 맥락으로, 프로젝트는 서로 다른 목표와 기술적 성격을 가진 작업 단위로, 각 사례는 프로젝트 안의 문제 해결 기록으로 표현한다.

## 정보 구조

```text
Selected Work
├── 아이쿠카 · Frontend Developer
│   ├── IQOOCCA Art Gallery 신규 앱 구축
│   │   └── E1–E8
│   └── 세바사 운영 앱 편입
│       └── E9–E13
└── Independent Project
    └── 릉릉
        └── 검증된 개인 기여 7개
```

회사 경력은 `아이쿠카`로 표시한다. 기존 `소프트자이온` 표기는 교체한다.

## 프로젝트와 URL

### IQOOCCA Art Gallery 신규 앱 구축

- 기존 URL `/projects/iqoocca-art-gallery`를 유지한다.
- 경력기술서의 E1–E8을 포함한다.
- E4 카카오 로그인과 E8 코나아이 웹뷰 이식은 `In Progress`로 표시한다.
- 신규 앱을 처음부터 구축하며 수행한 환경 분리, 네트워크, 인증, 디자인 시스템, 상태 관리, 심사 요건 대응을 중심으로 설명한다.

### 세바사 운영 앱 편입

- 새 URL `/projects/sebasa-grandparent`를 추가한다.
- 경력기술서의 E9–E13을 포함한다.
- 운영 중인 앱에 조부모 역할을 추가하면서 수행한 역할 확장, 후원 관문, AI 생성 상태 처리, 결제 웹뷰 복귀, 비가역 동작 UX를 설명한다.

### 릉릉

- 기존 URL `/projects/reungreung`와 현재 상세 내용을 유지한다.
- 아이쿠카 그룹 밖의 `Independent Project`로 표시한다.

## 데이터 모델

`Project`에 다음 정보를 추가한다.

- `company?: string`: 회사 소속 프로젝트의 회사명
- `category: "company" | "independent"`: 홈 그룹 분류

프로젝트 데이터는 세 항목이 된다.

1. `iqoocca-art-gallery`
2. `sebasa-grandparent`
3. `reungreung`

두 아이쿠카 프로젝트는 당분간 기존 IQOOCCA 대표 이미지를 공유한다. 새 이미지가 추가되면 각 프로젝트의 `image.src`만 교체할 수 있어야 한다.

## 홈 화면

`Selected Work`는 프로젝트를 평면 목록으로 바로 출력하지 않고 그룹 단위로 렌더링한다.

- 아이쿠카 그룹 헤더: 회사명과 직무를 표시한다.
- 회사 그룹 안에 IQOOCCA 신규 앱과 세바사 운영 앱 프로젝트 카드를 연속 배치한다.
- Independent Project 그룹 헤더 아래에 릉릉을 배치한다.
- 기존 카드의 이미지, 기술 스택, 상세 링크 표현은 유지한다.

그룹은 시각적 구분만 제공하며 별도의 회사 상세 페이지나 탭 인터랙션을 만들지 않는다.

## Experience 화면

- 회사명을 `아이쿠카`로 변경한다.
- 설명은 여러 모바일 프로젝트에서 신규 구축과 운영 앱 확장을 수행한 경험으로 수정한다.
- 책임 목록 아래에 두 프로젝트 상세 링크를 제공한다.
- `Experience` 타입에 선택적인 프로젝트 링크 배열을 추가한다.

## 프로젝트 상세 화면

- 각 페이지에는 해당 프로젝트 사례만 표시한다.
- 현재 `phase` 구분은 프로젝트 분리 후 불필요하므로 상세 화면의 Phase 구분 UI를 제거한다.
- `In Progress` 상태 배지는 IQOOCCA 신규 앱의 E4·E8에서 유지한다.
- 핵심 지표는 세바사 프로젝트에 배치한다. `53개 커밋`, `17개 페이지`, `18개 컴포넌트`, `14개 단위 테스트`는 운영 앱 편입 성과이므로 IQOOCCA 신규 앱 페이지에서는 제거한다.
- 상세 하단의 다음 프로젝트 링크는 slug 조건문 대신 프로젝트 배열 순서로 계산한다.

## 오류 및 빈 상태

- 알 수 없는 프로젝트 slug는 기존과 같이 404를 반환한다.
- 회사 프로젝트 링크가 없으면 Experience는 기존 텍스트 구조만 렌더링할 수 있어야 한다.
- 회사 또는 독립 프로젝트 그룹이 비어 있으면 해당 그룹 헤더를 렌더링하지 않는다.

## 테스트

- 프로젝트 데이터가 정확히 세 개이며 순서와 slug가 고정되는지 검증한다.
- IQOOCCA 페이지에는 E1–E8만, 세바사 페이지에는 E9–E13만 포함되는지 검증한다.
- E4·E8에만 `In Progress`가 표시되는지 검증한다.
- 홈에서 아이쿠카 그룹 아래 두 링크와 Independent Project 아래 릉릉 링크가 렌더링되는지 검증한다.
- Experience 회사명이 아이쿠카이며 프로젝트 링크 두 개가 렌더링되는지 검증한다.
- 세 상세 경로의 정적 파라미터와 메타데이터를 검증한다.
- 다음 프로젝트 링크가 데이터 순서를 따르는지 검증한다.
- 전체 테스트, 타입 검사, 린트, 프로덕션 빌드를 실행한다.

## 범위 밖

- 아이쿠카 회사 전용 상세 페이지
- 프로젝트 필터 또는 탭 UI
- 새 이미지 생성
- 경력기술서에 없는 프로젝트 추가
- 완료되지 않은 E4·E8을 완료 상태로 표현하는 작업
